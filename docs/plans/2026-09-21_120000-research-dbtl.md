# Codex-first Research DBTL

Approved direction: MVP 03, followed by explicit authorization to build Codex-first
coordination with roles configurable per project (2026-09-21).

## Goal and limits
One research project, a Codex skill and local browser panel backed by the existing
Hermes Kanban. Codex coordinates by default; Codex, Claude and Hermes can fill any
role. Roles are defaults for new tasks, not hard-coded model capabilities.
No new task database, MCP server, scheduler, automatic agent launches, accounts,
network service, source patch, or manuscript gate on internal reports.
Native Kanban handles claims, dependencies and task history; a thin script adds
DBTL evidence pins and review rules. This is the earliest extension surface that
supports Codex: a skill plus local scripts, packaged as a Codex plugin.

## Frozen interaction contract
Retain MVP03's four colored/icon lanes, compact cards, next-decision banner,
selected-card detail and expandable evidence/history. Replace simulated actions
with actual worker submissions and human approve/correct actions. The panel also
exposes project role defaults. Exploration is Design → Build → Learn. Test cards
require an explicitly selected manuscript claim and an independent worker.
Approval names the exact submission and scope. Changed files or changed upstream
pins make the handoff stale. Task status and receipts live in native Kanban;
project configuration contains only identity, board and role defaults.

## Isolation
Main checkout, branch main. New plugin, tests and this plan are isolated paths.
install.sh is clean and receives only opt-in installation support. README already
has unrelated edits and our sketch paragraph: preserve all unrelated hunks.
Do not touch dirty AGENTS.md, patches/desktop-research-workflow.patch,
scripts/reapply-desktop-patch.sh or tests/test_reapply_desktop_patch.py.
Do not modify approved sketch or copy private WikiHub content into this repo.

## Slices and proof
1. Scaffold plugin; native board adapter, project roles, claim/heartbeat,
   submission pins and dependency/review checks. Add failing behavioral tests
   before implementing the adapter, then run against a temporary native board.
2. Reimplement approved interface as static local assets served by stdlib HTTP.
   No fixture data in production. Strict loopback/token/Origin checks. Browser
   proof covers real temporary-project workflow, stale evidence, empty/loading/
   failure, narrow viewport and keyboard access. UI new-path red exception:
   browser journey is defined before implementation; no production UI exists.
3. Opt-in install.sh support, Codex skill and reproducible README commands.
   Install twice under temporary destinations, validate plugin/skill manifests.
4. Required Python and Node suites; code/security review, resolve findings and
   rerun affected checks. No commit, push, deploy or automatic background start.

## Boundary
Single machine and cooperative trusted local agents. The plugin checks ownership
and human approval through its entry points; full filesystem/native Hermes access
is not a security sandbox. Workers are user-started CLI sessions, not autonomous
cross-harness dispatch. A fresh Codex task discovers an installed plugin.
