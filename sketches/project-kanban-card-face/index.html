Deadline data source (open question, per the Issue Log): today's Kanban schema has no due-date field. This sketch's deadline row assumes a new optional field is added to the human-managed card's JSON metadata (e.g. project_kanban.due_date) — populated manually when a card is created/edited, the same way lane and project_id already work. "Approaching" threshold shown here is ≤7 days; needs your confirmation before it's built.
Card-type label logic: "Tracked" = card is linked to a canonical project with a GitHub/local Git evidence source; "Quick" = human-managed card with no linked repository evidence. Both pills reuse the existing project-linkage data already computed for the detail panel — no new backend field needed for this one.
This sketch is disposable and standalone: local CSS/JS only, no imports from plugin.js or plugin_api.py, no network, no build step. It demonstrates direction only — approval here authorizes a follow-up plan and vertical-slice build per hermes-customizations/AGENTS.md §3, not schema/backend changes on its own.
